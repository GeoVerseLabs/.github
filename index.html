GeoVerse SAR

MIT技术预览Technical preview

AI-native 空间应用运行时：人点 UI、AI 调工具、Agent 自主执行、外部 MCP 客户端，走同一个内核。

An AI-native runtime for spatial apps: UI clicks, AI tool calls, autonomous agents and external MCP clients share one kernel.

  • 能力描述符就是工具定义：同一份投影同时驱动 UI 命令面板、AI 工具目录与 MCP tools/list
  • 一切操作走单一漏斗 dispatcher.invoke：权限、校验、审计、事务日志回放长在内核里

  • A capability descriptor is a tool definition — one projection feeds the UI command palette, the AI tool catalogue and MCP tools/list
  • Every operation goes through one funnel, dispatcher.invoke: permissions, validation, audit and journal replay live in the kernel
  • Domain-state undo is first class: workflows collapse into one macro undo; writes can dryRun for human approval
  • The kernel depends only on zod and doesn't know what a map is; natural language never enters it — 425 tests run without a real LLM

Apache-2.0npm 0.3.0TypeScript

零依赖 TypeScript 库：在 GeoJSON 线网络上求带权最短路。

A zero-dependency TypeScript library for weighted shortest paths on GeoJSON line networks.

  • A*（可选 ALT 地标加速）/ Dijkstra / 双向 Dijkstra 按名切换，也能注册自己的引擎
  • 起终点吸附到线段任意位置；候选约束 + 全程择优；多途经点、跳过或直线兜底的失败策略
  • 0.3.0：多楼层室内寻路（电梯 / 楼梯 / 扶梯）、按节点编号建拓扑，建图提速约 2 倍
  • 同一份 13.5 万坐标路网、300 次查询：306 ms，0 条非最短路；geojson-path-finder 需 11.6 s 且有 41 条非最短†
  • A* (optionally ALT-accelerated), Dijkstra and bidirectional Dijkstra, switchable by name — or register your own engine
  • Snap endpoints anywhere on a segment; constrained candidates with cost-optimal selection; multi-waypoint routes with skip / straight-line failure policies
  • 0.3.0: multi-level indoor routing (elevators, stairs, escalators), node-id topology, ~2× faster graph builds
  • Same 135k-coordinate network, 300 queries: 306 ms with 0 non-shortest routes; geojson-path-finder took 11.6 s and returned 41†

04 · China's coordinate systems

同一个点，三套坐标One place, three sets of coordinates

国内图商的底图坐标经过国家规定的非线性偏移（GCJ-02），百度在此之上再加一层（BD-09）。偏移量随位置变化，通常在几百米——足以让一条路整体错开半个街区，又不至于离谱到让人立刻怀疑坐标系。

Chinese basemap providers shift coordinates with a mandated non-linear offset (GCJ-02); Baidu adds another layer on top (BD-09). The shift varies with location and is typically a few hundred metres — enough to move a street half a block, not enough to make anyone suspect the coordinate system.

GeoVerse 的做法：对外 API、数据库与 GeoJSON 一律 WGS-84；纠偏发生在引擎内部——OpenLayers 在投影层，MapLibre 在数据出入边界。两条路径，同一个对外契约。

How GeoVerse handles it: APIs, databases and GeoJSON are always WGS-84; correction happens inside the engine — at the projection layer in OpenLayers and at the data boundary in MapLibre. Two mechanisms, one public contract.

右侧换算在你的浏览器里实时计算（公开的 GCJ-02 / BD-09 近似算法），仅供理解偏移量级。

The conversion on the right runs live in your browser (the public GCJ-02 / BD-09 approximation) and is meant to show the magnitude of the offset.

06 · How we build

可证伪的工程纪律Engineering you can falsify

地图软件最危险的 bug 不报错，只是悄悄给出错的结果。所以我们把"怎么知道它是对的"放在和功能同样重要的位置。

The most dangerous mapping bugs don't throw — they quietly return the wrong answer. So "how do we know it's right" gets the same weight as the feature itself.

01

契约先于实现Contracts before implementations

坐标对外恒为 WGS-84；引擎独有能力不进统一接口；编辑内核的输入输出只有 GeoJSON，不知道地图库存在。

Coordinates are always WGS-84 at the boundary; engine-only features stay out of the shared interface; the editing core speaks only GeoJSON and never sees a map library.

02

门禁，而不是约定Gates, not conventions

依赖方向由 ESLint 门禁强制：editor-core 禁止 import 地图库，SAR 内核只能依赖 zod；跨入口一致性由测试钉死。

Dependency direction is enforced by lint gates: editor-core can't import a map library, SAR's kernel may only depend on zod, and cross-entry parity is pinned by tests.

03

四级状态口径Four-tier status wording

我们不说"做完了"，而是说清楚做到了哪一级——不让一句"完成"掩盖后三级的缺失。

We don't say "done"; we say which tier — so one word can't hide what's missing from the next three.

implementedverified-in-clean-CIpublishedproduction-supported
04

拒绝"假绿"No false greens

每个验证都要回答："如果没做对，它一定会失败吗？"WGS-84 底图全绿不代表纠偏正确；渲染问题回到真实浏览器，数据问题回到存储层核对。

Every check must answer: "if this were wrong, would it definitely fail?" Green on a WGS-84 basemap proves nothing about datum correction; rendering is verified in a real browser, data at the storage layer.

05

可复现的性能数字Reproducible numbers

基准取多轮中位数与区间，钉死对手版本，附复现命令；单轮测量不下结论，源码与构建产物不混比。

Benchmarks report medians with ranges over multiple rounds, pin competitor versions and ship a repro command; no conclusions from single runs, no source-vs-dist comparisons.

06

每个坑都沉淀成知识Every bug becomes knowledge

内部知识库 70 余篇知识笔记，其中 30 篇踩坑记录按"症状 → 真因 → 修法 → 复发防线"写成，并定期与代码对照防腐。

Our internal knowledge base holds 70+ notes, including 30 post-mortems written as symptom → root cause → fix → regression guard, and is re-verified against the code on a schedule.
